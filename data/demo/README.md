Здесь поставлен готовый пакет `package/` версии `tomsk-demo-1`: 500 тематических
объектов (123 школы, 104 медучреждения, 123 аптеки, 100 парков, 50 линий) и 4 района.
Он подготовлен из переданной разработчиком data.zip от 22.10.2026, SHA-256
`e57a050e0660738b2176fc7d31c410cd0d9773e183a45aa2ca9feda9574b9ec0`.
490 геометрий происходят из OSM, 10 искусственные. У 499 объектов есть искусственные
бизнес-свойства, явно отмеченные synthetic_fields; это демонстрационные данные.
© OpenStreetMap contributors, ODbL 1.0, https://www.openstreetmap.org/copyright.
Источники и даты встроены в data_sources файлов пакета; сервер считает метрики сам.

В Git хранятся только готовые GeoJSON и манифест. Исходная поставка, снимки OSM,
описание автора и материалы подготовки размещаются отдельно в
`MDP/datasets/tomsk-demo-1`. Для повторной адаптации из корня backend:

```powershell
python ops/prepare_demo.py --source-dir ../datasets/tomsk-demo-1
```

Скрипт проверяет SHA исходников, состав и сохранность прежних 28 объектов,
адаптирует properties.id в Feature.id, районные имена и добавляет schema_version/
data_sources. Геометрии и бизнес-поля не подменяются; исходный манифест данных
не является манифестом backend. Нативный манифест формируется отдельно.
Скрипт не пересобирает геоданные из OSM: это ответственность поставщика.
Проверки структуры и PostGIS выполняются штатной загрузкой до записи.
Повторная адаптация сохраняет байты пакета; изменение содержимого с тем же
package_version требует явного пересмотра версии поставки.

## Локальный стенд с Ollama и демонабором

```powershell
docker compose -f ops/compose.local.yml -f ops/compose.ollama.yml -f ops/compose.demo.yml up --detach --wait --wait-timeout 180 backend
```

Compose монтирует только `data/demo/package` read-only и задаёт DEMO_PACKAGE_DIR.
Автоматической замены БД при старте нет. Пустая БД: штатная CLI initialize ниже.
Непустая БД: admin API restore с confirm=true. При управлении стендом передавайте
все три Compose-файла; без compose.demo.yml пакет не подключается.
Для импорта слоя frontend: `data/demo/package/school.geojson` → `school` (123 школы).
Он заменяет слой полностью. Старый файл data/verification/imports/school.geojson
содержит 6 школ и нужен только для отдельного малого проверочного набора.

Доверенный пакет устанавливает оператор в каталог, заданный `DEMO_PACKAGE_DIR`.
Для контейнера его нужно смонтировать только для чтения и указать путь внутри
контейнера. API не принимает путь, URL или загружаемый архив.

Состав: `manifest.json`, `school.geojson`, `hospital.geojson`, `pharmacy.geojson`,
`park.geojson`, `improvement_zone.geojson`, `regions.geojson`.
GeoJSON соответствует схемам `contracts/import-thematic.schema.json` и
`contracts/import-regions.schema.json`. Каждый файл содержит ровно свой слой;
источники всех объектов должны быть описаны в `data_sources` хотя бы одного
файла пакета. Повторённые описания одного источника должны совпадать полностью.
Источники из текущей БД не дополняют неполный пакет.

Схема манифеста: [demo-manifest.schema.json](../../contracts/demo-manifest.schema.json).
Обязательны `schema_version: "1"`, непустая строка `package_version`,
`prepared_at` (RFC3339 с часовым поясом), непустое описание происхождения
`provenance` и список `files` с шестью элементами:

```json
{"layer_code": "school", "file": "school.geojson", "sha256": "SHA256_ИСХОДНЫХ_БАЙТОВ_ФАЙЛА"}
```

Это фрагмент структуры, не готовый манифест: замените SHA на 64 строчные
шестнадцатеричные цифры и добавьте остальные пять слоёв. Хешируется файл
целиком, включая BOM и переводы строк. Имена фиксированы; ссылки на файлы
вне каталога и симлинки не допускаются. Сам пакет должен происходить из
доверенной поставки: SHA-256 проверяет целостность, но не подписывает его.

Проверяются 350 точек суммарно в трёх непустых категориях school/hospital/pharmacy,
100 полигонов park, 50 линий improvement_zone и ровно четыре района:
Кировский, Советский, Ленинский, Октябрьский. ID тематических объектов уникальны
между всеми категориями. Геометрия, происхождение и метрики проходят общий
валидатор импорта; исправление геометрии автоматически не выполняется.

Применяются уже согласованные `IMPORT_MAX_FILE_BYTES`, `IMPORT_MAX_FEATURES`,
`IMPORT_MAX_POSITIONS`, `IMPORT_MAX_POSITIONS_PER_GEOMETRY` для каждого файла;
`IMPORT_TIMEOUT_SECONDS` — общий срок чтения/проверки/записи всего пакета,
`IMPORT_LOCK_TIMEOUT_SECONDS` — ожидание общей с импортом блокировки.
Размер manifest.json также ограничен `IMPORT_MAX_FILE_BYTES`.

Первоначальная загрузка: `python -m app.data_admin.demo_cli initialize`.
Она откажет, если геоданные уже есть или слой ранее импортировался.
Повторный вызов не перезаписывает набор. Восстановление выполняет администратор
через `POST /api/v1/admin/demo/restore` с JSON `{"confirm":true}`, Origin и CSRF.
Обе операции проверяют весь пакет до начала записи; заменяют геоданные,
справочники категорий и источников одной транзакцией; увеличивают общую версию
и обновляют все шесть layer_state. Аккаунты, сессии и настройки LLM сохраняются.
При ошибке до commit сохраняются прежние данные и метаданные целиком.

После начала COMMIT сервер ожидает подтверждения реального результата, поэтому
его ожидание может продлить общий срок обработки. При RESTORE_RESULT_UNKNOWN
нужно перечитать реестр/версию, а не автоматически повторять POST.
При отсутствии пакета возвращается 503 DEMO_PACKAGE_UNAVAILABLE, при повреждении
или неверном составе — 503 DEMO_PACKAGE_INVALID; данные не меняются.
