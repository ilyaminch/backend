# Проверочный набор Томска — ZTOZ-80/81

28 объектов: 6 школ, 5 медицинских учреждений, 8 аптек, 6 парков, 3 линейных
объекта благоустройства. Геометрии: 19 Point, 6 Polygon, 3 LineString.
Четыре административных района хранятся отдельно в `regions.geojson`.
Это малый проверочный набор; полная демоверсия на 500 объектов остаётся за его пределами.

## Сборка и проверка

Из корня репозитория, Python 3.12:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-geodata.txt
.\.venv\Scripts\python.exe -X utf8 scripts/verification_geodata.py build
.\.venv\Scripts\python.exe -X utf8 scripts/verification_geodata.py check
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -p test_verification_geodata.py
```

Сборка читает только [локальный архив OSM](../raw/README.md), проверяет его SHA-256
и перезаписывает `objects.geojson`, `regions.geojson`, `sources.json`.
Повторная сборка из того же архива даёт побайтово одинаковые файлы.
Для нового снимка нужно обновить путь к архиву, контрольную сумму, дату версии
и фиксированный список отбора в скрипте; затем повторить сборку и проверку.

## Нормализация и происхождение

- Формат соответствует [структуре ZTOZ-78](../../docs/verification-geodata.md).
  Координаты EPSG:4326, `[долгота, широта]`; `crs` и Feature.id не добавляются.
- 18 объектов имеют исходные геометрии OSM: 1 школа, 5 медицинских учреждений,
  5 аптек, 5 парков, 2 велодорожки. Отбор задан явными исходными ID в скрипте;
  разные точки и территории одного учреждения не включаются автоматически.
- Районные полигоны собраны из всех исходных `outer`-линий без исправления геометрии
  или упрощения. Неизвестные свойства — null, неизвестный статус — `unknown`.
- `wheelchair=yes/no` преобразуется в true/false; отсутствующее значение и `limited`
  дают null. Рейтинги, вместимости и даты открытия заданы для проверок и отмечены
  в `synthetic_fields`; это не фактические сведения об учреждениях.
- Площади и длины рассчитаны по геометрии на эллипсоиде WGS 84 (`pyproj.Geod`),
  округлены до 0,01 м²/м. Это вычисленные величины, не синтетические значения.
- У двух безымянных велодорожек технические названия с OSM ID, помеченные как
  синтетические. Использование велодорожек для `improvement_zone` — рабочее допущение.
- У 10 искусственных объектов `source: generated`, `source_id: null`, отмечены
  `geom`, название, статус и искусственно заданные бизнес-поля.
- ID исходных объектов: `OSM ID × 10 + тип` (node=1, way=2, relation=3).
  Искусственные ID: `9000000000000001`–`9000000000000010`.
  `updated_at` исходных объектов взят из XML; у искусственных фиксирован для версии набора.

## Граничные случаи и результат проверки

| Случай | Данные |
| --- | --- |
| Числовые пороги | Вместимости 199/200/201 и 499/500/501; рейтинги 3,9/4/4,1 |
| Отсутствующие и известные значения | null, вместимость 0, доступность true/false/null |
| Календарные даты | До/на/после границ 2016 года, 29.02.2024 |
| Последние 12 месяцев | Для запроса 10.10.2026: даты до/на/внутри/на/после окна 10.10.2025–10.10.2026 |
| Районы | По искусственной школе строго внутри каждого из четырёх районов |
| Касание границы | `9000000000000005` лежит на общей границе Кировского и Советского районов |
| Радиус | ID `9000000000000006`–`9000000000000008`: 499,9/500/500,1 м от `[84.95, 56.48]`; допуск проверки 0,000001 м |
| Пересечение районов | Линия `9000000000000009` и парк `9000000000000010` пересекают Кировский и Советский районы |

Проверка 10.10.2026: структура, ID, обязательные поля, типы и применимость свойств,
календарные даты, координаты, валидность геометрии, метровые величины, ссылки на
источники, совпадение исходных геометрий и наличие перечисленных случаев — успешно.
Все 7 автоматических тестов прошли; две повторные сборки побайтово совпали с сохранёнными файлами.
Пространственные примеры проверяют состав данных; исполнение JSON-фильтров относится к ZTOZ-86.
