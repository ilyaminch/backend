# Локальный стенд с внешним HTTPS-доступом

Схема: HTTPS ngrok → nginx со статической API-сборкой frontend → backend →
PostGIS и Ollama на Windows. Все браузерные запросы используют один Origin.
Frontend здесь — скомпилированный артефакт соседнего репозитория, его код не меняется.
Публичный Docker-проект — `mdp-review-stand`, со своей БД/томом и backend.
Он изолирован от разработки `mdp-backend-local`; admin restore проверяющих не меняет
локальную БД разработчиков. Порт nginx8088 опубликован только на loopback;
backend и БД публичного проекта вообще не публикуют порты.
Ollama не туннелируется. Образ nginx работает без root, read-only и закреплён digest.

## Конфигурация этого компьютера

- `.local/public.env`: единственный PUBLIC_ORIGIN=https://адрес-ngrok, без завершающего пути.
- `.local/public-frontend`: снимок frontend/dist, собранный с VITE_DATA_MODE=api.
- `.local/review_accounts.json`: отдельные review_user/review_admin и случайные пароли.
  Файл приватный, не попадает в Git или frontend; передавайте пароли проверяющим отдельно.
- Существующий `%LOCALAPPDATA%/ngrok/ngrok.yml` содержит токен ngrok; не копируйте его в Git.
- `.local/ngrok-stand.yml`: version2, web_addr127.0.0.1:4047, console_ui=false.
  API агента доступен только локально; inspect=false запрещает сохранение тел запросов агентом.
- ngrok установлен из официальной подписанной поставки в MDP/.tools/ngrok/ngrok.exe.

Полный Compose: local + ollama + demo + public, в этом порядке. Последний профиль
задаёт APP_ENV=demo, точный внешний PUBLIC_ORIGIN и COOKIE_SECURE=true.
Публичный backend принимает изменения только с внешним HTTPS-Origin. Для разработки
сохраняется отдельный backend localhost:8000 с Origin localhost:5173. Vite не публикуем
в интернет. Не используйте общий Compose project name для этих двух стендов.

## Запуск и восстановление

Из backend:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ops/start_public.ps1
```

Скрипт проверяет Docker, запускает Docker Desktop при необходимости, проверяет
публичный профиль/готовность API, поднимает контейнеры, запускает Ollama и восстанавливает
туннель строго на закреплённый адрес из public.env. Он не пересобирает приложения,
не импортирует геоданные и не меняет пароли. PID ngrok и технические логи находятся
в .local. Уже существующие несогласованные учётные записи provisioning не сбрасывает.
Геоданные — принятый пакет500+4, восстановление доступно только через admin API.

На этом компьютере зарегистрирована задача Windows `MDP-PublicStand`: при входе
пользователя и каждые две минуты запускается start_public.ps1 -Watch. Запуски
сериализованы файловой блокировкой; результат виден в Планировщике и .local/public-watch.log.
Проверка активности не генерирует запросы LLM за пользователя. Ошибки самой модели,
например CUDA при загрузке, диагностируются отдельно от доступности HTTP-сервисов.

Компьютер должен оставаться включённым, подключённым к интернету и питанию; после
перезагрузки нужен вход в Windows, чтобы работали Docker Desktop и пользовательская
задача. Не закрывайте крышку ноутбука, если это вызывает сон. Автосон от сети отключён;
прежняя настройка сохранена в .local/power-before-public.txt (настройки батареи не менялись).
Не отключайте обновления безопасности ради стенда; после перезагрузки проверьте доступ.

ngrok Free показывает посетителю страницу Visit Site перед первым входом и имеет
тарифные ограничения. Применимость и остаток квоты смотрите в аккаунте ngrok.
Адрес закреплён за аккаунтом; смена аккаунта/домена требует обновить public.env.
Сторонняя сеть также может блокировать ngrok — это нужно проверить у кураторов.

## Обновление frontend

После согласованного обновления соседнего frontend выполните там:

```powershell
$env:VITE_DATA_MODE='api'
npm.cmd run build
```

После успешной сборки скопируйте dist в backend/.local/public-frontend. Сохраняйте
предыдущий снимок до проверки нового; существующий снимок не обновляется автоматически
при работе frontend-агента. Это позволяет удерживать проверенную версию стенда.

## Остановка после завершения работ

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ops/stop_public.ps1
```

Скрипт создаёт .local/public.disabled, останавливает только наш туннель и frontend,
останавливает сервисы только публичного проекта. Локальная разработка не меняется.
Данные, аккаунты, Docker-тома и токен ngrok сохраняются. Watch-задача уважает маркер
и не откроет доступ заново. Ручной start_public.ps1 снимает маркер и включает стенд.
Для полного завершения также удалите свою задачу MDP-PublicStand и верните прежний
автосон от сети: на момент настройки он был 240 минут (`powercfg /change standby-timeout-ac 240`).

## Проверки перед передачей

Откройте публичную ссылку из внешней сети, пройдите Visit Site. Проверьте вход
обеих ролей, отображение500+4, поиск, карту, чат, admin импорт/restore. Проверки,
заменяющие данные, согласуйте с остальной командой. Secure/HttpOnly-cookie и CSRF/
Origin остаются включёнными; отключение проверок не требуется для туннеля.
